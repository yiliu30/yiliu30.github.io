🧠 The right mental model

01Dispatcher operates at block granularity. A core processes one block at a time, not a continuously scheduled pool of warps.
02Fetcher / decoder / scheduler are shared per core. All active lanes follow the same decoded instruction.
03ALU / LSU / register file / PC logic are per thread lane. Same instruction, different operands and results.
04Memory channels are shared. A request can finish after variable latency; the core waits before moving on.

⚠️ What this tiny GPU deliberately omits

No pipelined instruction overlap. FETCH → DECODE → REQUEST → WAIT → EXECUTE → UPDATE is a sequential control-state machine.

No warp scheduler or scoreboard. The simple core doesn't need out-of-order hazard tracking because it finishes the current instruction before fetching the next.

No branch divergence handling. The scheduler selects next_pc[THREADS_PER_BLOCK-1] as the shared next PC.

No RTL cache in the current src/ list. README discusses caching as a learning direction; the connected design uses memory controllers directly.
